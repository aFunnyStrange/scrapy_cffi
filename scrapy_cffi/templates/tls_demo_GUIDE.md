# TLS inspection demo

Generated by `scrapy-cffi demo -tls`. This demo performs only outbound HTTP
requests to public TLS diagnostic JSON endpoints; it does not require Docker,
Redis, or another queue.

Run it with:

```bash
cd demo
python runner.py
```

Edit `spiders/tlsSpider.py` and add curl_cffi built-in names or aliases from
your self-built artifact manifest to `impersonate_profiles`:

```python
impersonate_profiles = (None, "my-browser-stable")
```

The demo derives one stable `session_id` from each profile name. Requests for
the same profile reuse its own HTTP session and connection pool, while
different profiles never share a pool. This ensures that an existing
connection cannot hide the TLS handshake selected by a later profile.

For a self-built runtime, copy the native files using the structure documented
under `profiles/`, then set `SCRAPY_CFFI_CURL_CFFI_NATIVE_DIR` in `.env` to the
specific runtime directory. Profile selection remains explicit per request.

The endpoints are third-party diagnostic services intended for development
inspection. They require internet access and may apply their own availability
or rate limits.
