# 1.Introduction

`scrapy_cffi.mq` provides adapter classes with retry/reconnect support for `RabbitMQ` and `Kafka`.

Both managers keep explicit, IDE-visible public methods. They no longer use
`__getattribute__` to wrap every coroutine. Retryable I/O methods share a
single-flight reconnect controller: when many spider tasks observe one broker
failure, only one task rebuilds the transport and the remaining tasks reuse
the new generation. RabbitMQ channel-owned queue handles are invalidated on
reconnect; Kafka producer/consumer transports and registered callback
consumers are rebuilt together.

Install dependencies first:

```bash
pip install aio_pika
pip install aiokafka
```

Broker connection settings live in `settings.RABBITMQ_INFO` and `settings.KAFKA_INFO` (see [1-settings.md](./1-settings.md)). Redis scheduler/dedup uses `settings.REDIS_INFO`.

# 2. Local infra templates (`geninfra`)

Generate the independent Docker Compose stack for local development. It includes all supported state services: Redis, MySQL, PostgreSQL, MongoDB, RabbitMQ, and Kafka.

```bash
scrapy-cffi geninfra
./infra/init.sh       # Linux/macOS
./infra/init.ps1      # PowerShell
scrapy-cffi geninfra --all
./infra/init.sh --topology redis-cluster
./infra/init.ps1 -Topology kafka-cluster
./infra/destroy.ps1 -Topology kafka-cluster  # remove after debugging
scrapy-cffi geninfra --clean
```

Output defaults to `./infra/`:
- Baseline `docker-compose.yml` + `.env.example` (single-node infrastructure only)
- Cross-platform `init`, `reset`, and `destroy` scripts with `single`, `redis-sentinel`, `redis-cluster`, `rabbitmq-cluster`, and `kafka-cluster` selection
- Optional subdirs: `redis-sentinel/`, `redis-cluster/`, `rabbitmq-cluster/`, `kafka-cluster/`
- `production-endpoints.example.toml` — map real machine/DNS endpoints to `REDIS_INFO` / `RABBITMQ_INFO` / `KAFKA_INFO`; it is not a Docker deployment file

Each local topology uses a Compose project name derived from the crawler project directory, preventing containers and volumes from leaking across development projects. Reset removes only that project/topology.

The crawler's application Compose file contains only `app` and has no infrastructure dependency graph. In production, containerize only the crawler; connect directly to database/MQ machines or their native clusters through settings.

**Note:** Compose multi-container layouts simulate cluster/sentinel on one development host. They must never be used as a production deployment recipe.
The Kafka simulations use the official Apache Kafka KRaft image and do not require ZooKeeper.

CLI details: [0-start.md](./0-start.md#5geninfra).

# 3. Settings quick reference

## 3.1 Redis (scheduler / dedup / RedisSpider)

```python
from scrapy_cffi.models import RedisInfo

# Development single node
settings.REDIS_INFO = RedisInfo(URL="redis://127.0.0.1:6379/0")

# OR: production Sentinel machines (MODE is inferred)
settings.REDIS_INFO = RedisInfo(
    SENTINELS=[
        ("redis-sentinel-01.internal", 26379),
        ("redis-sentinel-02.internal", 26379),
        ("redis-sentinel-03.internal", 26379),
    ],
    MASTER_NAME="mymaster",
    USERNAME="crawler",
    PASSWORD="secret-from-env",
)

# OR: production Cluster startup machines (MODE is inferred)
settings.REDIS_INFO = RedisInfo(
    CLUSTER_NODES=[
        "redis-cluster-01.internal:6379",
        "redis-cluster-02.internal:6379",
        "redis-cluster-03.internal:6379",
    ],
    USERNAME="crawler",
    PASSWORD="secret-from-env",
)
```

Stream ingress defaults (optional, decoupled from spider attrs): `settings.REDIS_STREAM_INFO` — see [1-settings.md](./1-settings.md#293-redis_stream_info) and [2-spiders.md](./2-spiders.md#223-settingsredis_stream_info-project-wide-defaults).

## 3.2 RabbitMQ

```python
from scrapy_cffi.core.scheduler.rabbitmq import RabbitMqScheduler

# RabbitMQ carries requests; Redis is still required for distributed dedup.
settings.REDIS_INFO.CLUSTER_NODES = [
    "redis://redis-01.internal:6379",
    "redis://redis-02.internal:6379",
    "redis://redis-03.internal:6379",
]
# Real RabbitMQ machines; never use guest for remote production access.
settings.RABBITMQ_INFO.CLUSTER_NODES = [
    "amqps://crawler:secret@rabbitmq-01.internal:5671/scrapy",
    "amqps://crawler:secret@rabbitmq-02.internal:5671/scrapy",
    "amqps://crawler:secret@rabbitmq-03.internal:5671/scrapy",
]
settings.SCHEDULER = RabbitMqScheduler
```

## 3.3 Kafka

```python
# Kafka carries requests; Redis is still required for distributed dedup.
settings.REDIS_INFO.CLUSTER_NODES = [
    "redis://redis-01.internal:6379",
    "redis://redis-02.internal:6379",
    "redis://redis-03.internal:6379",
]
settings.KAFKA_INFO.CLUSTER_NODES = [
    "kafka-01.internal:9093",
    "kafka-02.internal:9093",
    "kafka-03.internal:9093",
]
settings.KAFKA_INFO.SECURITY_PROTOCOL = "SASL_SSL"
settings.KAFKA_INFO.SASL_MECHANISM = "SCRAM-SHA-512"
settings.KAFKA_INFO.SASL_USERNAME = "crawler"
settings.KAFKA_INFO.SASL_PASSWORD = "secret-from-env"
settings.KAFKA_INFO.SSL_CAFILE = "/run/secrets/infra-ca.pem"
settings.KAFKA_INFO.REPLICATION_FACTOR = 3
```

# 4. Integration tests

Unified broker test entry: `tests/test_broker/README.md`

Coverage:
- Redis: `single` / `sentinel` / `cluster`
- RabbitMQ: `single` / `cluster`
- Kafka: `single` / `cluster`

Stack assets: `tests/test_broker/stacks/{redis,rabbitmq,kafka}/`

Example (Linux/bash, from repo root):

```bash
docker compose -f tests/test_broker/stacks/redis/sentinel/docker-compose.yml up -d
python tests/test_broker/test_redis_broker.py sentinel
```

Legacy standalone dirs `tests/test_redis`, `tests/test_rabbitmq`, and `tests/test_kafka` were removed in 0.3.0; use `tests/test_broker` instead.
