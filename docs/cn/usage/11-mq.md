# 请求队列架构

[English](../../en/usage/11-mq.md) | 简体中文

Redis、RabbitMQ 与 Kafka 是平行的具体基础设施，不设置误导性的 `infra/broker` 父层。Redis List 与 Stream 本身也能承载任务。

Scheduler 依赖 `scrapy_cffi.repo.contracts`：`RedisRepositoryProtocol` 负责去重、Session、Redis Queue 与 Stream；`RequestQueueRepositoryProtocol` 负责发布、租约、确认、长度与临时清理。RabbitMQ/Kafka Repository 位于 `scrapy_cffi.repo.queue`，重试与客户端替换由 `ResourceService` 负责。

## 安装

```bash
pip install "scrapy_cffi[rabbitmq]"
pip install "scrapy_cffi[kafka]"
```

## RabbitMQ Scheduler

RabbitMQ 承载启动请求和增量请求；Redis 继续负责分布式去重和可选 Cookie/Session 持久化。

```python
from scrapy_cffi.config import RabbitMQInfo, RedisInfo
from scrapy_cffi.scheduler import RabbitMqScheduler

settings.REDIS_INFO = RedisInfo(URL="redis://127.0.0.1:6379/0")
settings.RABBITMQ_INFO = RabbitMQInfo(
    URL="amqp://guest:guest@127.0.0.1:5672/"
)
settings.SCHEDULER = RabbitMqScheduler
```

队列声明保持 `durable=True`、`auto_delete=False`。`SCHEDULER_PERSIST=False` 使用临时消息，并在正常退出和 Ctrl+C 时删除框架拥有的启动/工作队列。

## Kafka Scheduler

Kafka 分离 Start Topic 与 Work Topic，并只连续提交已经完成的 Offset：

```python
from scrapy_cffi.config import KafkaInfo, RedisInfo

settings.REDIS_INFO = RedisInfo(URL="redis://127.0.0.1:6379/0")
settings.KAFKA_INFO = KafkaInfo(URL="127.0.0.1:9092")
```

`QueueMessage` 是稳定交付模型；Scheduler 不导入 `aiokafka` Record 或具体 Kafka Client。

## 直接发布

```python
resources = build_resource_service(settings, asyncio.Event())
await resources.start()
try:
    await resources.rabbitmq.push("start_queue", b"https://example.com")
    await resources.kafka.push("start_topic", b"https://example.com")
finally:
    await resources.close()
```

Demo 还生成 `scripts/push_rabbitmq_demo.py` 与 `scripts/push_kafka_demo.py`。Kafka Helper 向 Start Topic 发布，运行中 Spider 产生的请求进入独立 Work Topic。

本地 `scrapy-cffi infra` 只生成开发依赖。生产 Crawler 直接连接独立部署的 Redis、数据库、RabbitMQ 与 Kafka；应用容器不拥有这些服务。
